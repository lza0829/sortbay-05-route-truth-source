# 分拣过机台（Sortbay）

骨架：过机扫描装载 → 口门路由裁决 → 错分回流批次 → 封袋班次对账

- 前端 http://127.0.0.1:6600
- API http://127.0.0.1:11600

## 已路由真源（全局唯一架构，禁止混用）

**以路由事件流水重放为准**：`route_events` 是已路由结果的唯一真源，
`scans.chute_id` / `scans.routed_event_id` 只是加速缓存。全局不采用
「以扫描口门列为准」的口径，任何面不得混用。

- **裁决写口**：`POST /api/扫描/{id}/路由`（`services/routed_truth.adjudicate`）
  是唯一同时写「事件 + 缓存列」的入口，两侧同事务；缓存列用条件更新兜底，
  并发双裁决一胜一败、败者整笔回滚，不漂一格。禁止只改口门数字。
- **同源展示**：扫描册、口门页在口件数、总览已路由桶、封袋页在口校验、
  审计重放全部经 `routed_truth` 重放取真源；缓存列仅作对照。
- **分叉必标**：缓存与真源不符时标 `事件缺失` / `列未动` / `旁路改列`，
  不得亮已对齐；假列在总览回落待路由桶。
- **旁路改列**：库外直改缓存列盖不住重放结果——展示仍显示真源，
  审计重放（`GET /api/审计/已路由真源`）现形，`POST /api/口门/校准`
  把缓存整笔回滚到真源并留审计，绝不反向改事件。
- **封袋在口校验**：只认真源口门。假列入袋一律 409 并留「入袋拒绝」审计；
  真源放行时缓存若陈旧，同事务顺手校准。
- **半截裁决**：写口事务保证不发生；库外造成的半截由对账标出、校准修复，
  列与事件不得长期分叉。

夹具（`backend/tests/test_routed_truth.py`）覆盖：旁路改口门列、
双裁决半截只落一侧、并发双裁决漂格、半截宕机整笔回滚、事件齐全列未动、
假列仍入袋（被拒并审计）、回流再路由事件链、规则漂移、封班对账假齐拦截。
